---

### STEP 1 — CURRENT STATE AUDIT (MANDATORY)

Before building anything:

- Scan the existing codebase
- Identify **every place** where:

  - A rule is already satisfied
  - A rule is partially implemented
  - A rule is violated
  - A rule is unenforced (possible to break)

Output a structured **Compliance Audit**:

```
Rule / Checklist Item
→ Status: PASS / PARTIAL / FAIL
→ Where implemented (file / component)
→ How it currently fails or can fail
```

No opinions. Only observable behavior.

---

### STEP 2 — GAP & RISK IDENTIFICATION

From the audit, identify:

- Which violations affect **end customers**
- Which violations affect **owner confidence**
- Which violations affect **performance, trust, or legality**
- Which violations are **structural** (can’t be fixed with styling)

Rank gaps by **severity**:

1. Critical (breaks constitution)
2. High (trust / usability violation)
3. Medium (enforcement missing)
4. Low (polish, not safety)

---

### STEP 3 — ENFORCEMENT DESIGN (NOT FEATURES)

For each violated or unenforced rule:

- Propose **hard constraints**, not suggestions
- Enforce via:

  - Types
  - Layout locks
  - Component boundaries
  - Editor limitations
  - Build-time or runtime guards

Examples of acceptable enforcement:

- Disabling layout combinations
- Locking font sizes / contrast
- Refusing publish if checklist fails
- Auto-correcting owner input
- Collapsing advanced controls behind safety checks

Examples of **unacceptable** responses:

- “We should guide the user”
- “We can show a warning”
- “Let the user decide”

---

### STEP 4 — IMPLEMENTATION PLAN (CODE-LEVEL)

Produce a **concrete implementation plan**:

For each enforcement:

- What component or module owns it
- What logic enforces it
- How violations are prevented (not warned)
- How legacy menus are handled safely

Assume:

- Tailwind CSS
- Framer Motion (used sparingly, never blocking)
- Mobile-first rendering
- Low-bandwidth environments

---

### STEP 5 — DEFAULTS & FAILURE MODES

Define:

- What happens when data is missing
- What happens when images fail
- What happens on slow network
- What happens if owner input is invalid

Defaults must always:

- Preserve readability
- Preserve trust
- Preserve speed
