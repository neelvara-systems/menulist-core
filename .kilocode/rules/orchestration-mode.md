## Mode-Specific Custom Instructions

### 1. Complex Task Decomposition Strategy

**Task Analysis Framework:**
- **Scope Identification**: Define the overall boundaries and objectives of the complex task
- **Natural Breakpoints**: Identify logical separation points where different expertise is needed
- **Dependency Mapping**: Map out relationships between different subtasks and their execution order
- **Mode Alignment**: Match each subtask with the most appropriate specialized mode
- **MenuList Constraints**: Ensure all subtasks respect constitutional governance and technical constraints

**Decomposition Principles:**
- **Single Responsibility**: Each subtask should have one clear, focused objective
- **Mode Expertise Match**: Delegate to the mode that best matches the subtask's requirements
- **Constitutional Compliance**: All subtasks must align with MenuList's 10 Laws and governance
- **Handoff Clarity**: Each subtask should produce clear outputs for the next phase

### 2. Subtask Delegation Protocol

**New Task Creation Standards:**
For each subtask, use the `new_task` tool with comprehensive instructions:

**Required Instruction Components:**
- **Complete Context**: All necessary context from parent task and previous subtasks
- **Defined Scope**: Exact boundaries and deliverables for the subtask
- **Exclusivity Statement**: Clear instruction to perform only outlined work
- **Completion Protocol**: Explicit instruction to use `attempt_completion` with thorough summary
- **Supersession Clause**: Statement that these instructions override conflicting mode instructions

**Subtask Instruction Template:**
```
**CONTEXT:** [Relevant background from parent task and previous subtasks]

**SCOPE:** [Exact boundaries and specific deliverables]

**EXCLUSIVITY:** Perform only the work outlined in these instructions. Do not deviate or expand scope.

**COMPLETION:** Use attempt_completion tool with a concise yet thorough summary of outcomes. This summary will serve as the source of truth for project tracking.

**SUPERSESSION:** These specific instructions supersede any conflicting general instructions your mode might have.

**MENULIST CONSTRAINTS:** [Relevant constitutional, technical, or documentation requirements]
```

**Mode Selection Guidelines:**
- **Architect Mode**: Planning, architecture design, requirements analysis, todo list creation
- **Debug Mode**: Problem diagnosis, systematic troubleshooting, bug resolution
- **Implementation Mode**: Code development, feature implementation, file creation
- **Documentation Mode**: Document creation, updates, organization, review

**Progress Management:**

## MenuList Orchestration Constraints

### Constitutional Governance
- **10 Laws Compliance**: All orchestrated workflows must respect MenuList's constitutional principles
- **3-Year Freeze**: No subtask should plan future phases or incomplete features
- **Infrastructure Identity**: Orchestrated workflows should reinforce MenuList as public utility
- **Zero Tolerance Bug Policy**: All subtasks must fix discovered issues immediately

### Technical Constraints
- **Version Freeze**: All subtasks must respect frozen dependency versions
- **Dual Platform Requirements**: Mobile support considerations across all relevant subtasks
- **Firebase Cost Awareness**: Cost implications considered in all data-related subtasks
- **Security Standards**: Security and type safety maintained across all subtasks

### Documentation Standards
- **7-Document Integration**: Documentation subtasks should produce complete document sets
- **Feature Flag Coordination**: Feature flag requirements coordinated across implementation subtasks
- **Mobile Support Planning**: Mobile documentation requirements included in relevant subtasks
- **Cross-Feature Consistency**: Documentation consistency maintained across all subtasks
