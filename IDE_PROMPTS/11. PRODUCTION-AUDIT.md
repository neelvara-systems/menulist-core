# Production Readiness Audit

Run the full 12-phase production certification audit for MenuList.

## Quick Start

1. Load master governance: `__docs__/testing-and-audit-prompts/00-master-production-audit-governance.md`
2. Execute phases 01-12 sequentially
3. Each phase produces its own report in `__docs__/testing-and-audit-prompts/reports/`

## Phase Index

| Phase | File | Focus Area |
|-------|------|------------|
| 01 | `01-core-codebase-system-foundation.md` | Architecture, dead code, error handling, TypeScript |
| 02 | `02-ai-system-cost-control.md` | AI usage map, token analysis, cost simulation |
| 03 | `03-firebase-infrastructure-scaling-cost.md` | Firestore, read/write patterns, scale cost |
| 04 | `04-authentication-access-control-tenant-safety.md` | Auth, roles, Firebase rules, tenant isolation |
| 05 | `05-security-hardening-owasp-vulnerability.md` | OWASP Top 10, input security, dependency scan |
| 06 | `06-customer-facing-experience-reliability.md` | Public menu, accessibility, Core Web Vitals |
| 07 | `07-smb-owner-ux-usability.md` | Owner UX, language governance, cognitive load |
| 08 | `08-full-system-dry-run-simulation.md` | Real usage simulation, Day 0-30 lifecycle |
| 09 | `09-failure-chaos-breakpoint-testing.md` | Network/AI/Firebase failure, chaos testing |
| 10 | `10-performance-speed-perception.md` | Speed, CWV benchmarks, SEO meta, mobile |
| 11 | `11-data-integrity-consistency-backend-safety.md` | Data consistency, race conditions, audit logs |
| 12 | `12-final-production-readiness-verdict.md` | Final verdict, launch confidence score |

## Final Deliverables

- `menulist-final-prod-readiness-report.md` — Launch readiness verdict
- `menulist-internal-security-certification.md` — Security trust certification
- `menulist-v2-future-opportunities.md` — Post-launch improvement log

## Execution Rules

- Follow master governance for ALL phases
- Only suggest: stability, security, cost, reliability, performance improvements
- Do NOT suggest feature additions or product expansion
- Every finding needs: severity, file reference, suggested fix, risk if ignored
- Each phase ends with confidence score /10
- Final question: "Would you launch this to paying SMBs today?" — Yes or No

## When to Run

- Before production launch (full 12-phase)
- After major feature completion (relevant phases only)
- Quarterly health check (phases 1, 3, 5, 10)
- After security concern (phases 4, 5)
- After cost concern (phases 2, 3)
