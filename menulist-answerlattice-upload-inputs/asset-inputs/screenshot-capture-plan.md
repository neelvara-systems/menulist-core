# Screenshot Capture Plan

## Objective

Capture MenuList and Answerlattice dashboard screenshots that can be used as product-proof inputs for Answerlattice website and marketing assets after MenuList is onboarded as a real Answerlattice production client.

The current package does not claim those screenshots are already captured from a live founder-approved production client. It prepares the capture list, privacy rules, file names, dashboard readiness requirements, and asset roles.

## Required Demo State

Use one founder-approved MenuList business/workspace across all MenuList captures.

Minimum data:

- 3 to 5 categories;
- 12 to 20 items;
- INR pricing;
- 4 to 6 clean item images;
- safe business name and logo;
- safe address and phone values;
- realistic business hours;
- one visible language switcher state;
- visible freshness/current-status signal;
- no real customer data;
- no owner email;
- no tenant/store/project IDs;
- no debug overlays.

## Required Answerlattice State

Before taking Answerlattice dashboard screenshots, MenuList must have:

- a production Answerlattice workspace;
- an active license;
- imported MenuList knowledge sources;
- reviewed KB and FAQ outputs;
- reviewed entity candidates and canonical answers;
- 8 to 12 mapped product surfaces;
- a production widget key;
- allowed origins locked to MenuList production hosts;
- widget runtime last-seen telemetry;
- page context received from MenuList owner routes;
- safe feedback/support signals.

Use `production-onboarding/dashboard-demo-data-requirements.md` as the readiness gate.

## Capture Rules

- Use Chrome for host-mapped custom-domain or authenticated dashboard proof.
- Use the in-app browser for simple localhost public-page checks.
- Keep private data scrubbed at source.
- Prefer real routed product surfaces over generated composites when a clean demo tenant exists.
- Preserve mobile and desktop proof.
- Do not run a Vercel deploy for screenshot capture unless explicitly requested.
