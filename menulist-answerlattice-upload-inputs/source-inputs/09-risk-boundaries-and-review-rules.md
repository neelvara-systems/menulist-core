# MenuList Risk Boundaries And Review Rules

## High-Risk Topics

Answerlattice should mark these MenuList topics as high-risk review before publishing:

- pricing and paid plan claims;
- subscription, billing, refunds, cancellation, invoices, and failed payments;
- privacy, security, legal, terms, and data deletion;
- external integrations and POS behavior;
- public discovery, SEO, AEO, ranking, citations, and agent-readable behavior;
- automatic publishing or automatic external sync;
- real customer proof, testimonials, logos, reviews, and screenshots;
- private data handling in screenshots or uploaded sources.

## Public Claim Rules

Allowed:

- MenuList prepares one official public version from an owner-approved source.
- Owners can start from a photo, PDF, existing menu link, or typed menu where supported.
- Public pages can expose structured, readable business/menu facts.
- Menu Kit creates print/social assets for placement.
- Digital Screens can show menu content from MenuList.
- External Menu Sync sends signed full-menu snapshots to connected configured URLs.

Not allowed without fresh implementation proof:

- MenuList automatically updates Google, Instagram, WhatsApp, or every external platform.
- MenuList guarantees search ranking, AI citation, or Google Maps placement.
- MenuList works with any POS.
- External Menu Sync is real-time bidirectional POS sync.
- Menu link import can crawl marketplaces, CAPTCHA pages, private dashboards, or login-protected sources.
- Answerlattice can use private MenuList tenant data as public proof.

## Screenshot Rules

Before a screenshot can be used broadly:

1. Use one founder-approved demo business.
2. Remove or avoid private owner details.
3. Hide tenant IDs, store IDs, project IDs, tokens, debug panels, service accounts, and internal URLs.
4. Use safe phone/address values.
5. Keep generated synthetic visuals labeled as generated demo visuals.
6. Keep private reference captures private unless separately approved.

## Answerlattice Review Rule

Every generated Answerlattice answer from this package should include source lineage and be reviewed before becoming official.

Canonical answers should be created as mutation proposals first when the topic is stable and support-worthy.

KB articles and FAQs can be drafted from this package, but they should not override Answerlattice doctrine or MenuList source truth.

## Answerlattice Product Boundary

Answerlattice is the Governed Answer Infrastructure.

When using MenuList as the example, avoid making Answerlattice look like:

- a helpdesk;
- a CMS;
- a generic chatbot;
- a MenuList feature;
- a restaurant/menu product;
- an external website asset product.

MenuList is the example product. Answerlattice remains the product that governs support knowledge.
