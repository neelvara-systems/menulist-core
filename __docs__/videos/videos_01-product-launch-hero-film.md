## Final Creative Thesis

This film tells a busy, non-technical owner:

```text
The menu or service list you already have can become one approved customer link,
without rebuilding everything or losing control of what customers see.
```

The film is one causal demonstration, not a feature montage:

```text
existing source
-> private customer preview
-> owner review and approval
-> one approved customer link
-> verified customer surfaces
-> controlled update
```

The hero is the approved customer version. AI is not the hero. QR is not the category. The dashboard is not the product story.

## Hand-Crafted Continuity System

The finished film must feel art-directed rather than assembled from unrelated scenes.

1. **One witness item:** Use one fictional item, such as `Cold coffee - 110`, in the source photo, old public versions, private preview, approved page, and update card.
2. **One source line:** A restrained MenuList-blue line traces that item's journey from source to preview to approved link to supported outputs. It communicates causality, not decoration.
3. **Shared-object transitions:** Item rows, status labels, URL fields, and QR geometry become the next scene's anchor. Do not cut through blank white frames.
4. **One proof surface at a time:** Each scene has one dominant product action. Supporting surfaces remain subordinate.
5. **Real UI over card theatre:** Use current MenuList capture at readable scale. No generic floating-card wall, repeated ghost words, page dots, top-left scene tags, nested cards, or heavy phone frames.
6. **Sparse website gradient:** Use the MenuList phrase gradient only on `approved customer link`, the private-to-approved state change, and the final identity treatment.

## Hook Decision

### Locked Hook

```text
That menu on your phone can become one approved customer link.
```

Why it wins:

- names the owner's existing asset;
- states the complete product outcome immediately;
- supports a visible source-to-preview transformation;
- does not use abstract sales language;
- keeps MenuList broader than a QR menu;
- remains factual without an unmeasured `in minutes`, `instant`, or `no work` promise.

### Hooks Not Used

| Rejected hook | Reason |
| --- | --- |
| `Your menu may be in five places.` | Familiar pain, but the product payoff arrives too late |
| `Introducing MenuList.` | Brand-first and weak in a skippable opening |
| `Do not type your menu again.` | Useful for a setup reel, but too narrow and too absolute for the flagship |
| `In the AI era, your business needs one public truth.` | Category thought leadership, not immediate owner proof |
| `Your QR still works. The page behind it may not.` | Strong pain reel, but it reduces the flagship opening to QR |

## E. Core Message

## F. Emotional Job

The viewer should think:

```text
I can start with what I already have, see the customer version before it is public,
and keep one link current without chasing every old file.
```

## G. Narrative Arc

Use a `BAB + demo loop` arc:

1. **After-first hook:** Show the desired outcome immediately.
2. **Before:** Reveal why scattered public versions remain a problem.
3. **Bridge:** Start from the owner's existing source.
4. **Demo cycle 1:** Source becomes a private customer preview.
5. **Trust turn:** Owner reviews and approves.
6. **Demo cycle 2:** Approved link supports verified customer surfaces.
7. **Customer outcome:** Current information and actions sit together.
8. **Update proof:** A change follows the same approval boundary.
9. **Brand resolution:** MenuList identity, tagline, and destination.

## L. Motion And Edit Direction

### Editorial Rhythm

```text
proof hit -> tension sweep -> guided intake -> transformation hold ->
review hold -> approval hit -> link reveal -> controlled expansion ->
customer hold -> update confirmation -> brand hold
```

### Motion Rules

- Create meaningful changes at approximately `0.0s`, `1.3s`, `2.8s`, and `4.5s` in the opening; they all advance the same transformation.
- Let later UI proof hold for two to four seconds where reading is required.
- Use shared-element focus pulls and velocity-matched overlaps, not hard white flashes.
- Keep the outgoing witness item or source line visible until the incoming scene has visual weight.
- Use cursor movement only for source selection, approval, one customer action, and update approval.
- Cursor settles before pressing and leaves after the result is visible.
- Use only one focal movement at a time.
- No repeated zoom pulse, endless floating, parallax wallpaper, neon glass, glitch, shader spectacle, or decorative card shuffle.
- Do not speed the complete master by ten percent after editing.

### Transition Map

| Seam | Transition |
| --- | --- |
| Source -> scattered versions | Witness item row expands into four concrete contexts |
| Scattered versions -> intake | Each old context collapses into its matching accepted source type |
| Intake -> private preview | Upload progress geometry becomes preview header and first category |
| Preview -> approval | Same witness item stays pinned while review controls move into focus |
| Approval -> customer link | Approved status feeds the source line into the URL field |
| Link -> supported surfaces | Source line branches without moving the approved link off-center |
| Customer view -> update card | Witness item row becomes the same item inside the prepared card |
| Updated item -> final slate | Updated row recedes while the complete logo scaffold is already visible; no blank frame |
