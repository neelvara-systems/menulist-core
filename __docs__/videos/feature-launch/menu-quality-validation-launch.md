# Feature Launch - Menu Quality Validation

**Status:** Script-ready; fresh runtime capture required before production
**Primary runtime rows:** `pricing_integrity` and current menu-quality/readiness signals
**Campaign authority:** [Feature Launch Inventory](./feature-launch-inventory.md)
**Mandatory standards:** [Founder-Approved Production Standard](../videos_founder-approved-production-standard.md), [HyperFrames Operating Guide](../videos_hyperframes-operating-guide.md), and [Asset Intake And Readiness](../videos_asset-intake-and-readiness.md)

## A. Purpose

Show how MenuList exposes concrete menu-readiness issues before customers encounter them, without implying automatic fixes or publishing.

## B. Audience

Owners and staff responsible for checking prices, categories, item details, and publish readiness.

## C. Placement

- Feature page.
- LinkedIn and Instagram.
- YouTube Short.
- WhatsApp sales.
- Retargeting.
- Onboarding and product demo.

## D. Recommended Duration

- Master: 35 seconds.
- Vertical cut: 25-30 seconds.
- Paid cut: 15 seconds.
- Silent UI proof loop: 8 seconds.

## E. Core Message

MenuList identifies menu-readiness issues and guides the owner to the right fix before publishing.

## F. Emotional Job

`I can catch a wrong or incomplete menu before customers depend on it.`

## G. Narrative Arc

1. **Hook:** A missing price is already a customer problem.
2. **Problem:** Small menu gaps are difficult to spot across a long list.
3. **Product entry:** MenuList checks current menu readiness.
4. **Proof:** The owner sees exact issues and opens the affected item.
5. **Outcome:** The list is reviewed before public release.
6. **CTA:** Catch issues before customers do.

## K. UI Screens Required

- Customer menu item with a controlled missing-price fixture.
- Current quality/readiness issue list.
- Missing-price issue detail.
- Empty-category or incomplete-detail issue, only if current runtime supports it.
- Deep link from issue to editor item.
- Corrected item review.
- Resolved readiness state with separate publish action.

## L. Motion Design Direction

- Enter on product evidence, not an abstract warning card.
- Move focus from issue to exact owner action.
- Limit motion to one highlighted row and one cursor path.
- Use a gentle zoom of no more than 6% on the correction moment.
- Keep the publish boundary visible after resolution.
- Use direct cuts on action changes and 6-10 frame overlap on scene changes.
- Keep captions clear of issue labels and buttons.

## M. Sound Direction

- Use the approved `One Link Motion v2` bed at restrained density.
- Add one soft alert texture at the missing-price reveal.
- Add one click for opening the item and one muted confirmation for resolution.
- Keep the music under voice and recover slightly after the issue is resolved.
- Do not use error sirens, warning buzzers, or gamified celebration sounds.

## N. Design Checklist

- [ ] Every visible validation type exists in current runtime.
- [ ] Missing data uses fictional demo content, never a real customer mistake.
- [ ] The owner action is specific and readable.
- [ ] Validation is not portrayed as autonomous correction.
- [ ] Publishing remains separate and owner-controlled.
- [ ] No health score, percentage, or readiness metric is invented.
- [ ] No red-heavy fear treatment is used.
- [ ] Mobile text remains readable after platform compression.
- [ ] Final identity is plain and non-clickable.
- [ ] Encoded output passes visual and audio QA.

## P. CTA

## Q. Conversion And Claim Contract

- **Conversion job:** Build confidence that MenuList supports careful publishing, not merely fast publishing.
- **Primary proof:** One current issue opens the exact editor action and resolves without automatic publication.
- **Allowed:** Current runtime checks and owner guidance shown exactly as implemented.
- **Required:** A visible owner-review and publish boundary.
- **Blocked:** Perfect-menu claims, automatic fixes, invented readiness scores, or guaranteed prevention of every error.
- **Release gate:** Revalidate the check types, issue wording, deep-link behavior, and corrected state against the current runtime.
