```text

```

The [feature launch inventory](./feature-launch-inventory.md) is the decision authority for which product capabilities receive a dedicated launch video, which are combined into another story, which belong in onboarding/tutorial content, and which must not be marketed.

## Shared Production Contract

Every feature launch must:

1. Lead with one owner or customer problem, not the feature name alone.
2. Show the real MenuList action or result inside the first six seconds.
3. Use one dominant proof surface per scene.
4. Preserve private preview and owner approval wherever public truth can change.
5. Distinguish MenuList-controlled outputs from links the owner places externally.
6. Avoid rankings, revenue lift, automatic external updates, fake numbers, and AI-magic framing.
7. Use the current [founder-approved production standard](../videos_founder-approved-production-standard.md), [HyperFrames operating guide](../videos_hyperframes-operating-guide.md), and [asset readiness gate](../videos_asset-intake-and-readiness.md).
8. Render locally with HyperFrames only; no paid, hosted, account-backed, or Remotion production path.
9. Close the encoded MP4 with the approved identity only: MenuList symbol, `MenuList`, `One approved customer link`, and `menulist.ai`.
10. Put the clickable conversion action in the surrounding placement, platform CTA, post, or sales message.

## Versioning

Each feature keeps its own semantic sequence:

```text
ml-fl-<feature-slug>-v1.0
ml-fl-<feature-slug>-v1.1
```

Create `v1.0` only when the first review MP4 exists. Increment the version only for a rendered review pass, and record the exact change in the campaign ledger. Plans and scripts do not reserve version numbers.

## Readiness Boundary

- native aspect-ratio QA;
- founder approval of the encoded MP4;
