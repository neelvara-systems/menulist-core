## Core Decision

MenuList has two PWA audiences, not one PWA per public surface.

| Audience | Origin | Manifest | Service Worker | Identity |
| --- | --- | --- | --- | --- |
| Owner | Platform/dashboard origins | Owner dashboard manifest | `public/sw.js` generated by `next-pwa` | MenuList owner app |
| Customer | Tenant subdomains and custom domains | `src/app/manifest.webmanifest/route.ts` | `public/sw-customer.js` | One store-branded Customer App per tenant store origin |

Installing from OBP, `/menu`, or a project slug must produce the same store app identity. Public routes and project slugs are in-app navigation/source attribution only.

## Manifest Contract

The Customer App manifest is store-level.

| Field | Current Policy |
| --- | --- |
| `id` | Stable per store: `/?store={storeId}` |
| `scope` | `/` on the tenant origin |
| `start_url` | `/menu` when an active customer menu exists, otherwise `/` |
| `name` | Store/public presence display name |
| `short_name` | `pwaSettings.pwaShortName` if set, otherwise derived from store name |
| `theme_color` | `publicPresence.accentColor` when valid, otherwise platform default |
| `background_color` | White |
| `orientation` | `portrait-primary` |
| `categories` | Defaults to `food`, `business`, `lifestyle` |
| `screenshots` | Generated narrow and wide screenshots |
| `shortcuts` | Store-level app actions, not separate app identities |

Important rules:

- The manifest route is `/manifest.webmanifest` on the tenant origin.
- The manifest does not consume `?start=` for identity.
- Deleted or renamed project slugs do not define installed app identity.
- `MANIFEST_START_URL_DEGRADED` is no longer part of this architecture.
- `pwaInstallSurface` is analytics source context only.

## Service Worker Contract

Customer App uses `public/sw-customer.js`.

Frozen rules:

- No menu content caching.
- No Firestore API caching.
- No `/_client/*` page caching.
- No Workbox runtime caching for tenant-facing menu routes.
- Offline means branded offline page only.
- Never serve a stale cached menu as a fallback.

Owner dashboard can keep `next-pwa`/Workbox behavior through `public/sw.js`, but tenant/customer origins must use the minimal customer SW.

## Menu Freshness Contract

Customer App freshness uses existing server truth propagation.

Flow:

1. Owner saves menu data.
2. Existing save path calls `revalidateMenuCache(storeId)`.
3. Vercel edge tag for that store is invalidated.
4. Customer launch/navigation fetches fresh server-rendered menu.
5. If a customer returns to a stale open tab after at least 60 seconds hidden, `useMenuFreshness()` calls `router.refresh()`.

What this does not do:

- No Firestore listeners.
- No periodic polling.
- No version-check endpoint.
- No forced update banner.
- No extra Firestore reads for unchanged menus.

The hook has a refresh cooldown to avoid repeated `router.refresh()` calls during rapid app switching.

## Icon And Screenshot Contract

Current implementation is endpoint-driven, not a pre-generated storage pipeline.

### Icons

Route: `src/app/api/app-icons/[storeId]/[size]/route.tsx`

Supported sizes:

- `180` for Apple touch icon usage
- `192`
- `512`

Resolution order:

1. Redirect to `publicPresence.pwaIconOverrideUrl` if set.
2. Redirect to store logo if it is a usable image URL.
3. Generate deterministic first-letter PNG with `ImageResponse`.

### Screenshots

Route: `src/app/api/app-screenshots/[storeId]/[formFactor]/route.tsx`

Supported form factors:

- `narrow` -> 1080 x 1920
- `wide` -> 1920 x 1080

The manifest includes both generated screenshots for richer install UI support.

Not current runtime:

- No `/api/app-icons/generate` route.
- No Sharp-based background icon generation job.
- No persisted generated icon variants in Firebase Storage except owner-uploaded overrides.

## Install Prompt Contract

Current install prompt logic lives in `src/components/customerApp/CustomerAppController.tsx`.

Eligibility:

- `FEATURE_FLAGS.ENABLE_CUSTOMER_APP_PWA` must be on.
- `pwaSettings.promoteInstallation !== false`.
- Customer must not already be in installed/standalone mode.
- Visit threshold must pass, defaulting to 3 visits.
- A 30-day dismissal suppression window must not be active.
- Direct install intent via `?pwa=install` bypasses the visit threshold but still respects dismissal suppression.

Prompt storage:

- Visit count uses `localStorage`.
- Dismissal timestamp uses `localStorage`.
- Session/open dedupe uses `sessionStorage` where appropriate.

Prompt analytics:

- Prompt shown, dismissed, and install-started events fire from `InstallPrompt.tsx`.
- Native `appinstalled` is handled by `CustomerAppController`.
- iOS manual install is inferred on first standalone launch through `standaloneDetector.ts`.

## Shortcuts Contract

Current shortcuts are app actions inside the same store app.

| Shortcut | Condition | URL Strategy |
| --- | --- | --- |
| View Menu | Always | Store-level `start_url` with `source=shortcut-menu` |
| Call | Phone exists and public call action enabled | Same-origin `/pwa/call` handoff |
| Directions | Maps URL exists and public directions enabled | Same-origin `/pwa/directions` handoff |
| WhatsApp | WhatsApp number exists and public WhatsApp enabled | Same-origin `/pwa/whatsapp` handoff |
| Reservation | Reservation URL exists | Same-origin `/pwa/reservation` handoff |
| Order Online | Order URL exists | Same-origin `/pwa/order` handoff |

Shortcut URLs include source attribution for analytics. They do not imply separate installed apps.

## Analytics Contract

Customer App is a store-level surface and writes into the existing analytics system with reserved `projectId='customerApp'`.

Current event set:

- `CUSTOMER_APP_PROMPT_SHOWN`
- `CUSTOMER_APP_PROMPT_DISMISSED`
- `CUSTOMER_APP_INSTALL_STARTED`
- `CUSTOMER_APP_INSTALLED`
- `CUSTOMER_APP_OPENED`
- `CUSTOMER_APP_SHORTCUT_MENU`
- `CUSTOMER_APP_SHORTCUT_CALL`
- `CUSTOMER_APP_SHORTCUT_DIRECTIONS`
- `CUSTOMER_APP_SHORTCUT_WHATSAPP`
- `CUSTOMER_APP_SHORTCUT_RESERVATION`
- `CUSTOMER_APP_SHORTCUT_ORDER`

Daily doc:

`{tId}_{sId}_customerApp_daily_{YYYY-MM-DD}`

Summary doc:

`{tId}_{sId}_customerApp_overall_summary`

Dashboard summary doc:

`{tId}_{sId}_customerApp_dashboard_summary`

Tracked metric families:

- Prompt funnel totals.
- Installed/device-install totals.
- Standalone app opens.
- Shortcut clicks.
- Device/location/platform/source breakdowns.
- Surface/source attribution maps.
- Hourly prompt/open buckets.

Aggregation:

- `functions/src/aggregateCustomerAnalytics.ts` includes Customer App fields in daily aggregation, lifetime summary updates, correction deltas, and map merging.
- `functions/src/analytics/dashboardSummaryAggregation.ts` builds the dashboard-ready Customer App summary and daily map.
- Nested map fields are additive-only. Keys are summed, not replaced.

Privacy and owner controls:

- `analytics.trackCustomerApp` inherits from `trackMenuViews`.
- If menu analytics are disabled, Customer App analytics are disabled.
- No customer identity, device fingerprint, heatmap, or person-level install tracking is introduced.
- iOS installs are inferred because Safari does not fire `appinstalled`.

Important wording:

- `pwaInstallSurface`, `installsBySurface`, and `appOpensBySurface` are source attribution only.
- They do not mean separate installed apps for OBP/menu/project pages.

Owner reporting:

- Desktop: `src/components/templates/main-app/dashboard/AnalyticsDashboard/CustomerAppMetrics.tsx`
- Mobile: `src/components/mobile/screens/dashboardSections/MobileCustomerAppMetrics.tsx`
- Dashboard data hook: `src/hooks/useCustomerAppDashboard.ts`
- Dashboard read path: `src/database/ownerDashboard/index.ts`

## Owner Readiness Status

Customer App settings show a read-only status card on desktop and mobile.

Status rows:

- `Installable`: whether `pwaSettings.enableInstallableApp` is active.
- `Install link`: whether a tenant subdomain/custom domain exists for sharing.
- `App icon`: whether a custom override is active or the system is using automatic logo/letter fallback.
- `Install prompt`: whether promotion is active or install is manual-only.

This is intentionally informational. It does not expose manifest, service-worker, cache, or browser internals to SMB owners.

## Engineering Guardrails

- Do not add customer menu content caching to `sw-customer.js`.
- Do not add Workbox runtime caching for tenant-facing menu routes.
- Do not reintroduce per-route manifest identity.
- Do not treat source attribution as installed app identity.
- Do not introduce a new Customer App analytics collection.
- Do not introduce customer identity/fingerprinting for install dedupe.
- Do not use `next@latest`; this repo keeps the frozen Next.js version.
- Any change to install identity, service-worker scope, or analytics document shape must update this file, `customer-app_spec.md`, `customer-app_test.md`, and `customer-app_firebase.md` together.
