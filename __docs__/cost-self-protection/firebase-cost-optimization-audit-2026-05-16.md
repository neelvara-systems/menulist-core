## Flow Decisions

- Public menu and OBP reads are already cache-first with `unstable_cache`, React request dedupe, and cache tags. More aggressive TTL would reduce reads but risks stale public truth after owner changes.
- Digital screens require realtime updates because screen content must refresh without staff intervention. The listener is a direct document listener, which is the correct low-cost shape.
- Multi-outlet inheritance must not be cached beyond the existing public cache envelope because linked outlet rendering depends on master truth.
- MCE stays zero-cost because it validates in memory and stores metadata inside the existing project write.
- MOL event writes are retained. They are write amplification, but they are also the governance trail for master/outlet changes.
- Analytics writes are retained because they feed owner dashboards. The queue/debounce/rate-limit layer now also drops duplicate same-session item impressions and short search noise.
- Auth session reads are security-sensitive. The session callback now uses a short 15-second process-local burst cache and forces a fresh read on explicit session updates so `active`, `blocked`, tenant-block, and store-block freshness remains bounded.
- Support ticket full inboxes keep realtime. The Help Center landing summary now uses a one-time bounded read, and a selected ticket drawer attaches only a single-document listener while open.
- Public sitemap outlet discovery is summary-first. The legacy collection query remains only for older `storesSummary` documents without routable outlet fields.

## Optimizations Applied

| Change | Before | After | Cost effect | Safety reason |
| --- | --- | --- | --- | --- |
| Batch image listener bound | Project listener could read every queued/processing/completed/failed job for that project. | Query adds `limit(1)`. | Reduces listener initial reads and update fanout for projects with retained result jobs. | UI already used only `jobsList[0]`; this preserves the visible contract. |
| Batch image status writes narrowed | Status-only updates also wrote `generatedCount: 0`. | `generatedCount` is written only when caller passes a generation-count update. | Removes unnecessary field writes and prevents completed/cancelled/finished flows from resetting count state. | Initial job creation already stores `generatedCount: 0`; progress updates still use `increment(1)`. |
| Screen seen write dedupe | If client localStorage failed or reset, the server could write once per hour. | Existing doc read checks `screen.screenLastSeenAt`; same UTC day returns cached success without a write. | Bounds liveness writes to documented 1/day/screen behavior. | Client already uses UTC date keys, and screen output never depends on this field. |
| Owner dashboard legacy overview | Legacy overview called full weekly dashboard path to get `aiSummary`, causing summary + weekly reads. | Overview reads only the current/fallback weekly doc for AI summary; weekly view now returns `aiSummary` directly. | Saves one summary read and avoids extra transform work on legacy overview calls. | Same weekly docs are used; settled dashboard read model remains unchanged. |
| Auth session burst cache | Each session refresh could reread the user document plus tenant/store block context. `trigger === "update"` also reread twice. | JWT callback uses a 15-second process-local cache for routine refreshes and a forced fresh read on explicit session update. User lookup queries now use `limit(1)`. | Reduces repeated owner navigation/session-check reads while bounding security-state staleness to seconds. | Login and explicit session updates still read fresh authority state; block inheritance remains applied before session payload creation. |
| Public analytics batching and noise filter | Public events flushed after 15 seconds or 20 queued events, duplicate same-item PDP opens could increment item views, and one-character searches could write noisy map keys. | Flush window is 30 seconds / 40 events, same-session item view duplicates are skipped, and search terms must normalize to at least two characters. | Fewer write batches, fewer repeated item counters, and fewer high-cardinality search-map writes. | Analytics is additive owner reporting; customer rendering and ordering flows do not depend on these writes. |
| Help Center landing ticket summary | Landing card attached a store-ticket realtime listener even when the owner was not in the ticket inbox. | Landing card uses the existing bounded `getStoresTickets()` read; opening one ticket attaches a single ticket-document listener only while that drawer is open. | Removes a passive collection listener from Help Center home loads. | The summary is only a preview, and the opened conversation still updates live. |
| Sitemap outlet enumeration | Multi-outlet sitemap cache misses queried the `stores` collection by tenant. | Sitemap reads `platformSummary/storesSummary` first and falls back to the collection only when summary data is missing or not routable. | Avoids broad tenant outlet collection reads on normal sitemap generation. | Existing fallback preserves legacy tenants until summary backfill is proven complete. |
| Public routing fallback verifier | Legacy OBP/sitemap collection fallbacks had no repeatable readiness check for removal. | Added a read-only Admin SDK verifier for `storesSummary`, outlet slugs, block/active state, and `projects_{storeId}` slug coverage. | Enables safe future removal of fallback collection reads after a verified backfill. | The script performs no writes and does not affect runtime routing. |

## Before / After Cost Impact

| Flow | Before | After |
| --- | --- | --- |
| Batch image generation listener | Up to N matching job docs per project listener mount/update. | 1 matching job doc per listener mount/update. |
| Batch image status updates | Status updates could rewrite `generatedCount` even when the count was not changing. | Status updates write only status/history fields; progress writes still increment count. |
| Digital screen liveness | Intended 1 write/day from client, but server fallback allowed hourly writes if local storage did not hold. | Server enforces same-day skip using the already-read summary doc. |
| Legacy dashboard overview | 2-3 reads for weekly path when only AI summary was needed. | 1-2 reads for current/fallback weekly AI summary only. |
| Auth session refresh | Routine refreshes could reread user + tenant + store context repeatedly during navigation. | Routine refreshes within 15 seconds reuse sanitized process-local context; explicit session updates force a fresh read. |
| Public analytics | Smaller batches plus duplicate item views and one-character searches could still create extra writes. | Larger batches, same-session item impression dedupe, and normalized search terms reduce public write volume without dropping core dashboard metrics. |
| Help Center landing | Help Center home mounted a passive store-ticket collection listener. | Help Center home performs one bounded read; the ticket inbox keeps its collection listener, and the summary drawer listens only to the selected ticket document while open. |
| Sitemap outlets | Tenant outlet collection query on sitemap cache miss. | One summary document read on normal cache miss; legacy collection fallback only when summary data cannot safely render outlets. |

No new collections, indexes, dependencies, feature flags, or public routing contracts were introduced.

| Legacy collection fallbacks | Reduced, watch | Sitemap outlet fallback is now summary-first. A read-only verifier now checks whether `storesSummary` and `projects_{storeId}` are complete enough for fallback removal; fallbacks remain until that verifier passes for the intended scope. |

### Rejected From This Pass

- No blind composite-index deletion; index cleanup still requires query-to-index mapping and usage evidence.
- No blanket `.limit()` changes on list screens; pagination/UX changes need per-surface decisions.
- No published immutable snapshot rewrite; that remains a separate architecture decision touching routing, publish, OBP, multi-outlet, SEO, and cache invalidation.
- No dependency upgrades despite Firebase CLI warnings about `firebase-functions`; dependency freeze remains in force.
- No immutable cache metadata on fixed-path logo/profile/font/template uploads because those paths can be overwritten and would risk stale assets.
- No immutable cache metadata on legacy project/notes fallback uploads where the file ID can be reused by the same logical record.
