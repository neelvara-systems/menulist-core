## §1 — Positioning

### One-Line Pitch
"Canonica sends knowledge governance digests and critical alerts to Slack or email — so founders know when support answers need review before users notice."

### Elevator Pitch (30 seconds)
"Every SaaS team has knowledge that goes stale — API docs change, features sunset, pricing updates. Canonica detects when support knowledge drifts from product reality and sends bounded review signals to Slack or email. No dashboard-checking loop. No noisy event stream. Knowledge governance delivered where founders already work."

---

## §2 — Key Selling Points

### For SaaS Founders
- **Zero monitoring burden** — Governance events come to you, not the other way around
- **Instant drift awareness** — Know when a canonical answer is stale within minutes of detection
- **Knowledge gaps → review work** — Recurring support friction becomes a reviewable Canonica task; issue tracker creation is controlled rollout
- **Weekly digest** — One email summarizing everything Canonica did this week

### For Engineering Leads
- **Support signals → review items** — Convert "users keep asking about X" into actionable Canonica review work
- **Product friction detection** — Know which features cause the most support friction
- **No Slack bot complexity** — Simple notifications, not interactive workflows

### For Support Managers
- **Coverage drop alerts** — Know immediately when canonical coverage falls below threshold
- **AI failure alerts** — Know when AI can't answer recurring questions
- **Hands-free governance** — Canonica monitors, you only act when notified

## §3 — Competitive Differentiation

| Feature | Canonica | Zendesk | Intercom | Freshdesk |
|---------|----------|---------|----------|-----------|
| Knowledge drift detection → Slack | ✅ | ❌ | ❌ | ❌ |
| Knowledge gap → review queue | ✅ | ❌ | ❌ | ❌ |
| Canonical coverage alerting | ✅ | ❌ | ❌ | ❌ |
| Event-driven (not polling) | ✅ | ✅ | ✅ | ✅ |
| Governance-focused events | ✅ | ❌ (ticket events only) | ❌ (conversation events only) | ❌ (ticket events only) |

**Key differentiator:** Canonica's integrations are **governance-aware**. Competitors send ticket/conversation events. Canonica sends **knowledge health events** — drift, gaps, coverage, mutation proposals. This is a different category of integration.

## §4 — Sales Objection Handling

| Objection | Response |
|-----------|----------|
| "We already have Slack integrations with Zendesk" | "Zendesk tells you about tickets. Canonica tells you about knowledge health — when answers are stale, when there's a gap, when coverage drops. Different signal, different value." |
| "Can it create Jira issues?" | "Self-service v1 focuses on Slack/email alerts. Issue tracker creation is controlled rollout until credential handling is self-service safe." |
| "We don't use Slack" | "Email notifications are included. Weekly digest email summarizes all governance activity." |
| "How much does this cost?" | "Included in your Canonica subscription. No per-event pricing. No API call charges." |
