# MenuList Marketing Distribution - 100 SMB Lists Ops Playbook

**Status:** Draft ops playbook, not approved to run  
**Created:** June 23, 2026  
**Owner:** Founder with Codex acting as MenuList marketing consultant  
**Related action:** MLD-W007  

---

## Purpose

This playbook defines the launch stunt:

> 100 SMB Lists in 100 Hours

It must not run until production WhatsApp readiness, intake ownership, proof permissions, tracking, and capacity are confirmed.

---

## Campaign Promise

Use:

> Send your current list. MenuList prepares one official customer link.

Use in WhatsApp-first markets:

> Send your current list on WhatsApp. MenuList turns it into one official customer link.

Do not use:

- guaranteed live in minutes
- official WhatsApp partner
- automatic WhatsApp Catalog sync
- reply `APPROVE` to publish
- ranking, sales, revenue, or traffic claims
- "free forever" or unlimited manual setup

---

## Run Gate

The challenge can run only when all P0 gates are done:

| Gate | Required state |
| --- | --- |
| Production WhatsApp number | Confirmed and tested |
| Response owner | Named |
| Response hours | Confirmed for all 100 hours |
| Manual lead board | Ready with consent, state, and follow-up fields |
| Preview capacity | At least 25 qualified list previews per day can be handled |
| Proof permission script | Ready |
| Demo fallback assets | Ready if real proof is delayed |
| Public counter rules | Approved |
| Stop rule | Approved |

If any P0 gate is not ready, run a 10-list private pilot instead.

---

## Qualification Rules

Count only a business that sends a real current list and fits MenuList:

Accepted:

- menu
- service list
- rate card
- package list
- price list
- catalog
- PDF/photo/screenshot/link/text list

Rejected or parked:

- no current list available
- request is only for booking/POS/delivery software
- regulated/sensitive vertical that needs review
- business refuses review/approval step
- owner asks for external-platform sync as the main need
- source is too unclear and no replacement is sent

## Workflow

| Step | Owner action | Operator action | Board state |
| --- | --- | --- | --- |
| 1 | Sends list on WhatsApp/upload path | Acknowledge and request missing essentials | List received |
| 2 | Sends business name, city, list type | Qualify and assign preview owner | Qualified |
| 3 | Waits for preview | Prepare public preview or request clearer source | Preview preparing |
| 4 | Reviews preview | Send review link and checklist | Preview sent |
| 5 | Sends corrections or approval through the real approved path | Apply corrections or publish only through supported runtime path | Approved / Corrections |
| 6 | Receives official customer link | Send placement checklist and staff reply template | Public link live |
| 7 | Places link on 2 surfaces | Record activation surfaces | Activated |

Approval must map to the runtime's actual approved path. Do not publicly claim WhatsApp reply-command approval.

---

## Public Counter Rules

The public counter can show:

- lists received
- previews prepared
- public links approved
- categories represented

The public counter must not show:

- real business names without permission
- revenue/conversion claims
- fake progress
- businesses that only asked questions but did not send a list
- private phone numbers or file names

Recommended counter labels:

| Label | Meaning |
| --- | --- |
| Lists received | Current list source is in hand |
| Previews prepared | MenuList preview was created |
| Approved links | Owner approved public version |
| Activated links | Link placed on at least two customer surfaces |

---

## Proof Assets

Use this proof order:

1. fictional demo transformations;
2. permissioned anonymized transformations;
3. permissioned named businesses;
4. public case studies only after owner approval.

Every public before/after asset must include:

- source type;
- business type;
- city/country if approved;
- "sample" or "used with permission" label;
- no private phone numbers, owner names, or customer details unless approved.

---

## Content Cadence

Minimum daily cadence during challenge:

| Surface | Output |
| --- | --- |
| LinkedIn | Founder update with one learning |
| Instagram/Reels | One before/after or demo transformation |
| WhatsApp Status | Counter update and CTA |
| X | Short progress thread or objection response |
| Internal board | Full state update |

Do not publish a real business asset faster than permission can be verified.

---

## Stop Rules

Pause or shrink the challenge if:

- response time exceeds the promised operating window;
- preview backlog exceeds one day;
- unclear sources are increasing and operators cannot recover them;
- opt-out or complaint signals appear;
- proof permissions are not being recorded;
- public copy starts drifting into unsupported platform claims;
- product/runtime issue blocks preview, approval, or publish flow.

---

## Success Metrics

Primary metrics:

- current lists received
- qualified lists
- previews prepared
- approvals
- official customer links live
- two-surface activations
- paid conversions
- partner leads

Secondary metrics:

- content saves/shares
- qualified comments
- referral leads
- repeat vertical patterns
- objections logged

Do not treat views or upvotes as success unless they lead to current lists, partner conversations, or activated public links.

---

## Pilot Version

Before the 100-hour public challenge, run:

> 10 SMB Lists in 10 Days

Pilot goals:

1. test response load;
2. test proof permission script;
3. test lead board states;
4. identify unclear source patterns;
5. validate whether owners place the link on two surfaces.

Do not run the public 100-list version until the pilot produces clean operational evidence.
