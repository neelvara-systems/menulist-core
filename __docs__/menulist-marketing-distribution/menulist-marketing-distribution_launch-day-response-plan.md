# MenuList Marketing Distribution - Launch-Day Response Plan

**Status:** Draft operating plan  
**Created:** June 22, 2026  
**Owner:** Founder runs, Codex maintains docs  
**Related action:** MLD-L003  

---

## Purpose

This plan defines how MenuList should respond during a Product Hunt or public launch day.

It does not schedule the launch, post comments, send DMs, create Product Hunt assets, or automate replies.

---

## Launch-Day Goals

Primary:

1. answer every useful question with factual boundaries;
2. route qualified SMB owners to current-list intake;
3. route agencies/freelancers to partner conversation;
4. route multi-location operators to consistency review;
5. capture objections and proof gaps for follow-up.

Secondary:

- upvotes;
- comments;
- social shares;
- press/investor interest.

Do not treat leaderboard rank as the main success signal.

---

## Response Roles

| Role | Owner | Responsibility |
| --- | --- | --- |
| Founder voice | Founder | Maker comment, high-signal replies, partner/multi-location conversations |
| Product/funnel watcher | Codex or team member | Watch route issues, CTA confusion, docs gaps, screenshots/assets |
| Lead tracker | Founder or assistant | Add every useful lead to follow-up board |
| Escalation owner | Founder | Pricing, legal, partnership, investor, press, sensitive complaints |

---

## Time Blocks

| Window | Focus |
| --- | --- |
| T-60 to T-15 minutes | Verify launch page, website link, Product Hunt assets, CTA paths, response docs, tracking sheet |
| Launch hour 0-2 | Founder answers every useful Product Hunt comment quickly and plainly |
| Hour 2-6 | Route owner/partner/multi-location leads; post LinkedIn launch note; watch funnel health |
| Hour 6-12 | Reply to late questions; collect objections; update FAQ/reply bank |
| Hour 12-24 | Follow up qualified leads manually; record source, state, and next action |
| Day +1 | Review metrics, blockers, proof gaps, and next content |

The response clock is subordinate to the approved work-in-progress limit. If
qualified intake exceeds the number of previews and follow-ups the team can
serve accurately, pause new promotion, state the delay plainly, and finish the
existing queue before adding attention.

---

## Comment Routing

| Signal | Public reply | Private/manual follow-up |
| --- | --- | --- |
| SMB owner asks how to try it | Ask for current list or route to `/create-menu` | Add to follow-up board |
| Agency/consultant asks about clients | Use partner angle | Send partner brief after founder approval |
| Multi-location operator asks | Mention consistency review | Founder handles |
| SEO/AI-search question | State crawlable/structured public info; no guarantee | Log as education topic |
| QR menu comparison | Explain QR is one surface | Link Product Hunt reply bank answer |
| Booking/POS comparison | Clarify non-replacement | Log if many people ask |
| Pricing question | Give approved pricing/pilot answer only | Founder handles |
| Press/investor | Thank and route to founder | Founder handles |
| Bug report | Acknowledge, ask for details | Route to product issue tracker |
| Off-topic | Reply once if useful | No follow-up |

---

## Reply Boundaries

Use:

- "owner-approved public customer link";
- "current menu, service list, package list, catalog, or price list";
- "QR, WhatsApp, Instagram, Google/profile links, print, and repeat-customer access";
- "Search engines and external platforms decide what they crawl, index, show, or update."

Do not use:

- "rank";
- "guaranteed SEO";
- "more sales";
- "automatic Google update";
- "AI will get you discovered";
- "replace booking";
- "replace POS";
- "all-in-one SMB platform."

## End-of-Day Review

Record:

- number of useful comments;
- number of current-list leads;
- number of partner leads;
- number of multi-location leads;
- top five objections;
- questions that need website copy updates;
- any route/runtime issue;
- screenshots or assets that confused people;
- next-day follow-up owner.
