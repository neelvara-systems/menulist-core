## Feature Narrative

### The Problem

Writing menu descriptions is harder than it looks:

- **Time-consuming:** Manual writing adds work item by item
- **Inconsistent:** Different items get different quality
- **Copywriting skills:** Not everyone can write appetizingly
- **Multi-language:** Even harder in multiple languages

Many menus end up with bland or missing descriptions.

### The Solution

MenuList Description Preparation:

- **Draft-first:** Description suggestions are prepared for owner review
- **Editable:** Owners approve the final wording before publishing
- **Language-aware:** Language scope follows configured project support and release evidence
- **Batch-friendly:** Selected menu items can be prepared together

### The Result

Menu descriptions start from a review draft instead of a blank field, while the owner keeps final approval.

## Sales Talking Points

### Objection: "AI descriptions will sound robotic"

**Response:** "MenuList generates professional, natural-sounding descriptions. Most customers are surprised by the quality. And you can always edit any description if you want to add your personal touch."

### Objection: "I want unique descriptions"

**Response:** "Every description is generated specifically for your item. Two restaurants with 'Butter Chicken' get different descriptions based on context."

### Objection: "What about dietary info and allergens?"

**Response:** "Allergen information needs to be accurate for legal compliance, so that's something you add separately. Descriptions focus on making items sound appetizing—allergens are handled in dedicated fields."

### Objection: "Can I edit after generation?"

**Response:** "Absolutely. MenuList gives you a professional starting point, then you customize as needed. Most users make minor edits or none at all."

## Positioning Notes (Internal)

### Authority-First Framing

MenuList **prepares** descriptions as part of menu digitization—not as a separate tool the user operates.

**Say:** "Your menu descriptions are prepared"
**Don't say:** "Click here to generate descriptions"

### Silence = Confidence

If descriptions are already complete, the feature is invisible. This is correct.

**Say:** "MenuList helps prepare menu content for review"
**Don't say:** "Generate descriptions anytime"

### No Encouragement of Regeneration

Avoid language that trains users to "try again" or "experiment with styles."

**Say:** "Edit any description to your preference"
**Don't say:** "Don't like it? Regenerate with different settings"
