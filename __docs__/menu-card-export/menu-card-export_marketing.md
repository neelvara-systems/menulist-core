## Positioning

Menu Card Export creates print-ready menu files from the current MenuList menu.

The point is not "PDF generation." The point is that print becomes another operating surface tied to MenuList truth.

---

## One-Line Pitch

MenuList creates printable menu files from your current menu.

---

## Narrative

Owners already print menus, send PDFs on WhatsApp, and hand files to print shops. The problem is that those files drift from the live menu. Prices change online, the printed card stays old, and staff/customers see different information in different places.

Menu Card Export keeps the printable menu connected to the same menu truth used by the QR menu and official business page.

The routed workflow adds the missing operational pieces: print preset, preview, preflight warnings, QR check, print-shop packet, and stale-file history.

The no-designer workflow is intentional. MenuList first picks a business-aware print layout, density, and safe display options from the current menu, catalog, or service list. Pro/Premium layout suggestion is an extra review layer, not the baseline way to make the PDF look acceptable.

## Differentiation

| Alternative | What it does | MenuList position |
| --- | --- | --- |
| Canva-style menu design | Gives owners templates and editing tools | Too much owner work; separate content source |
| Basic PDF download | Dumps menu data into a file | Useful but not enough as a print surface |
| Designer-made menu card | Looks good once | Can go stale immediately after a menu change |
| Print-shop-only workflow | Requires separate file preparation and owner coordination | MenuList creates a packet the owner can send |
| MenuList Menu Card Export | Creates controlled print output from current menu truth | Consistent, current, low owner effort |

## Approved Talking Points

- Generated from the current MenuList menu.
- Print-ready menu files.
- Choose Home Print, WhatsApp PDF, or Print-shop packet.
- Preflight catches common print problems before export.
- QR points customers to the latest menu.
- The route shows whether an older export still matches the menu.
- MenuList picks a safe starting layout so owners do not need to design.
- Pro and Premium can request an extra layout check before export.

## Packaging Notes

Suggested entitlement model:

| Capability | Starter | Pro | Premium |
| --- | --- | --- | --- |
| Default Classic export | Yes | Yes | Yes |
| Compact and Premium styles | Limited | Yes | Yes |
| Export history | Last 3 | Last 20 | Higher limit |
| WhatsApp PDF | Yes | Yes | Yes |
| Print-shop packet | No | Yes | Yes |
| Layout suggestion | No | Yes | Yes |
| Multi-location batch export | No | No | Yes |

The basic export must remain useful. Paid gating should focus on history, style range, print-shop outputs, layout suggestions, and multi-location operations.

## Support Framing

When an owner asks why a PDF is outdated:

> Create it again from MenuList. The new file uses the current menu.

When an owner asks to move items manually:

> The layout is handled automatically so the menu stays consistent.

When an owner asks what to send to a printer:

> Use the print-shop packet. It includes the PDF and printing notes in one download.

When an owner asks for a custom design:

> MenuList creates menu cards from your current menu. Custom design files should stay outside MenuList.
