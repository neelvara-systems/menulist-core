# AUTHORITY ENFORCEMENT POLICY

**Document Type:** Governance  
**Last Updated:** 2026-01-11  
**Status:** 🔒 LOCKED  
**Audience:** Sales, Support, Engineering, Marketing

---

## PURPOSE

This document defines what MenuListAi team members can and cannot say about the system.

**Core Principle:**  
MenuListAi does not explain itself. It earns trust through consistent behavior.

---

## FORBIDDEN PROMISES

Never promise or imply these capabilities:

| Forbidden                    | Why                                |
| ---------------------------- | ---------------------------------- |
| "We'll add X feature"        | Creates feature creep expectations |
| "You can customize logic"    | Undermines authority               |
| "We'll show you the data"    | Invites debate                     |
| "The AI will improve"        | Sets uncontrollable expectations   |
| "You can override decisions" | Breaks trust model                 |

---

## FORBIDDEN EXPLANATIONS

Never explain the following:

| Topic                     | Why Forbidden          |
| ------------------------- | ---------------------- |
| Confidence scores         | Invites gaming         |
| Scoring formulas          | Creates support burden |
| Why specific items appear | Undermines authority   |
| How AI works              | Unnecessary complexity |
| Why something is missing  | Silence is a feature   |

---

## FORBIDDEN ACTIONS

| Action                            | Why Forbidden               |
| --------------------------------- | --------------------------- |
| Manually override recommendations | Breaks system trust         |
| Share raw analytics               | Undermines authority        |
| Expose debug logs                 | Security + complexity       |
| Compare campaigns for users       | Creates decision fatigue    |
| Promise timeline for fixes        | Uncontrollable expectations |

---

## APPROVED MESSAGING

### When Asked "How Does It Work?"

**Approved:**

```
"MenuList observes what your customers like and tells you
what to promote. Just follow what the Today tab shows."
```

**Not Approved:**

```
"Our AI analyzes customer behavior using confidence scores
and machine learning to determine optimal recommendations."
```

### When Asked "Why Am I Seeing This?"

**Approved:**

```
"Because it's working well with your customers.
You can skip if you prefer, but we recommend following it."
```

**Not Approved:**

```
"This item has a confidence score of 0.78 based on
clicks, views, and engagement metrics."
```

### When Asked "Why Is There Nothing Today?"

**Approved:**

```
"There's nothing urgent to promote right now. That's okay!
Check back tomorrow."
```

**Not Approved:**

```
"The system didn't find any items meeting the 0.6
confidence threshold for today."
```

### When Asked "Can I See the Data?"

**Approved:**

```
"MenuList keeps things simple by not exposing raw data.
Just follow what appears—it's based on real behavior."
```

**Not Approved:**

```
"We can export your analytics dashboard showing
clicks, views, and conversion metrics."
```

## RESPONSE FRAMEWORK

### S.A.F.E. Protocol

| Step          | Action                             |
| ------------- | ---------------------------------- |
| **S**implify  | Reduce to one-sentence answer      |
| **A**uthority | Speak with confidence, not apology |
| **F**orward   | Redirect to action, not discussion |
| **E**nd       | Don't invite follow-up questions   |

### Example Application

**Bad:**

```
"That's a great question! So, what happens is our system
uses machine learning to analyze various signals like
clicks and views, and then we calculate a confidence
score. When that score is above 0.6, we show you a
campaign. Does that make sense? Do you have any
other questions?"
```

**Good:**

```
"It's based on how your customers behave.
Just follow what it shows."
```

---

## ESCALATION

If a user insists on:

- Seeing raw data
- Understanding the formula
- Getting manual overrides

**Escalate to:** Product Lead

**Do not:**

- Explain further
- Apologize
- Promise changes
