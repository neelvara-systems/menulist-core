# 🔒 MENULIST AUTHORITY MANIFESTO

**Version:** 1.0  
**Created:** January 9, 2026  
**Status:** 🔒 **INTERNAL LAW — NON-NEGOTIABLE**  
**Authority:** Maximum — Overrides all other considerations  
**Applies To:** All employees, contractors, sales reps, support agents, and future hires

---

## Purpose

This document defines how MenuList behaves, how humans around it behave, and what is **never allowed**.

This is **not marketing**. This is **internal law**.

Everyone is bound by this. Violation is grounds for escalation.

---

## 🧠 Core Definition

> **MenuList is an autonomous decision system.**
> It does not assist owners.
> It does not explain itself.
> It acts.

MenuList earns trust by being **rarely wrong**, not by being verbose.

---

## 🧱 The 10 Laws of MenuList

### **Law 1 — Default Authority**

MenuList decides by default.
Owner action is optional, temporary, and reversible.

---

### **Law 2 — Silence Is a Feature**

If MenuList has nothing to act on, it does nothing.

Silence means:

- No banners
- No nudges
- No suggestions
- No "insights"

Silence = confidence.

---

### **Law 3 — No Explanations**

MenuList never explains _why_ it made a decision.

No:

- Scores
- Percentages
- Comparisons
- Attributions
- Causal claims

If a decision needs explanation, it should not have been made.

---

### **Law 4 — Owners Override, Systems Resume**

Owners may override temporarily.

The system **always resumes control** automatically.

Permanent overrides are a system failure.

---

### **Law 5 — Public Surfaces Demand Perfection**

Anything visible to customers (screens, QR, posters) must be:

- Conservative
- Stable
- Availability-safe
- Embarrassment-proof

MenuList would rather show less than show wrong.

---

### **Law 6 — No Cognitive Load**

If a feature causes the owner to think, compare, choose, or analyze — it does not ship.

MenuList removes decisions.
It does not add better ones.

---

### **Law 7 — No Feature Without Autonomy**

If a feature cannot act autonomously, it is not a MenuList feature.

Dashboards do not qualify.

---

### **Law 8 — Trust > Engagement**

We do not optimize for:

- Time spent
- Clicks
- Usage
- Activity

We optimize for:

- Zero-intervention days
- Public reliance
- Owner silence

---

### **Law 9 — Humans Do Not Patch Trust**

Sales, support, or marketing must never compensate for system weakness with explanations.

If trust breaks:

- Fix the system
- Not the story

---

### **Law 10 — Authority Is Fragile**

Once trust is broken, it is almost impossible to restore.

Every decision must assume:

> "This will be publicly visible and remembered."

---

## 🚫 SALES LANGUAGE BLACKLIST

**Absolute Prohibitions**

Sales does **not** explain how MenuList works.
Sales does **not** promise outcomes.
Sales does **not** sell intelligence.

**Sales sells relief.**

---

### ❌ NEVER SAY (Instant Disqualification)

| Forbidden Phrase         | Why It Destroys Trust                 |
| ------------------------ | ------------------------------------- |
| "MenuList analyzes…"     | Invites scrutiny of analysis          |
| "Our AI decides…"        | Makes AI the subject, not the outcome |
| "Based on data…"         | Implies data can be questioned        |
| "Optimized for…"         | Invites "optimized for what?"         |
| "Improves conversion…"   | Promise without ownership of funnel   |
| "Increases sales…"       | Unverifiable claim                    |
| "Boosts revenue…"        | Unverifiable claim                    |
| "Trending items…"        | Implies volatility                    |
| "Best performing…"       | Invites comparison requests           |
| "Recommended by AI…"     | Makes recommendation debatable        |
| "Compared to last week…" | Invites analytics questions           |

These words **destroy authority**.

---

### ✅ ALWAYS SAY (Approved Language)

| Approved Phrase                  | Why It Works             |
| -------------------------------- | ------------------------ |
| "MenuList runs your menu."       | Operational certainty    |
| "This updates automatically."    | No action required       |
| "You don't need to manage this." | Removes cognitive load   |
| "It keeps itself up to date."    | Continuous, not episodic |
| "You can ignore this."           | Permission to forget     |
| "It handles this daily."         | Reliability              |
| "Nothing to configure."          | Zero decisions           |
| "If it's shown, it's safe."      | Trust in public surfaces |

Sales is allowed **only operational certainty**, never intelligence claims.

---

### 🧩 Approved One-Line Pitch

> **"MenuList runs your menu and in-store decisions automatically.
> You don't manage it — you just let it work."**

Nothing else.

## 🛠️ SUPPORT RESPONSE RULES

**This is where most systems die — read carefully.**

Support exists to restore **operation**, not **confidence**.

---

### ❌ Support Must NEVER:

- Explain _why_ an item was shown
- Explain _how_ the system decides
- Share internal signals or confidence
- Compare items
- Speculate
- Justify outcomes
- Educate users on decision logic

**If a ticket asks "why", support must not answer the "why".**

---

### ✅ Support IS Allowed To:

- Confirm whether something is working
- Fix broken behavior
- Remove incorrect public content
- Escalate confidence breaches
- Acknowledge limitations calmly

---

### 🧠 Approved Support Templates

#### If user asks: "Why did MenuList show this item?"

**Correct Response:**

> "MenuList only shows items it's confident are appropriate at that time.
> If something looks incorrect, we'll fix it."

---

#### If user asks: "How does this decide?"

**Correct Response:**

> "MenuList runs automatically based on live menu conditions.
> It doesn't require configuration."

---

#### If user says: "I don't agree with this decision."

**Correct Response:**

> "You can skip or override it.
> The system will adjust automatically."

---

#### If user says: "Can I control this more?"

**Correct Response:**

> "MenuList is designed to reduce management, not add it."

---

#### If user asks: "What data are you using?"

**Correct Response:**

> "MenuList uses your menu and customer engagement.
> There's nothing to configure."

---

#### If user asks: "Is this AI?"

**Correct Response:**

> "MenuList runs automatically. You don't need to manage it."

(Do NOT confirm or deny "AI" — it invites debate.)

---

### 🚨 Mandatory Escalation Rule

If **3 or more users** ask "why" about the same behavior:

- Support does NOT explain
- Support escalates to product
- Product fixes the system or suppresses the behavior

**Explanations are never the fix.**

## 📊 METRICS WE TRACK (Internal Only)

These metrics measure **trust**, not **usage**.

| Metric                           | What It Measures                  | Target             |
| -------------------------------- | --------------------------------- | ------------------ |
| **Zero-Intervention Days (ZID)** | Days owner doesn't touch system   | ↑ Higher is better |
| **Public Surface Trust Rate**    | Screen active time vs preview     | > 95%              |
| **Override Half-Life**           | How long overrides last           | < 48 hours         |
| **Support Ticket Intent Ratio**  | "Why" tickets vs "broken" tickets | < 10% "why"        |
| **Today Completion Rate**        | Actions completed vs shown        | > 70%              |
| **Empty-State Retention**        | Users who stay despite no action  | Parity with active |

**The Meta-Metric:** "How boring is MenuList on a good day?"
