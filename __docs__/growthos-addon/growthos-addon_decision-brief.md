# GrowthOS Add-on - Decision Brief

**Status:** Active planning decision
**Decision date:** May 31, 2026
**Recommended path:** Build GrowthOS as a paid MenuList add-on for higher-tier clients.

---

## Recommendation

Proceed with GrowthOS only as a MenuList add-on.

Do not build it as a separate product now. Do not ship the paused Weekly Growth Pack as the main product. Do not enter the generic marketing-design category.

The winning shape is narrow:

> MenuList knows what is true today. GrowthOS turns that truth into something the owner can use today.

## Why Not Standalone

Standalone SMB marketing generation is already being attacked by large platforms.

| Competitor motion | Risk |
| --- | --- |
| Google Pomelli generates on-brand campaigns from a business website. | Google can own generic SMB campaign creation and may connect it to search/ads over time. |
| Canva Visual Suite and Magic Studio cover campaign design, resizing, brand kits, and scaled creative work. | Canva owns the broad creative surface and power-user design workflow. |
| Adobe Express and similar suites target brand-safe business creative production. | Broad design/editing is not MenuList's strongest angle. |
| Social schedulers and local SEO tools already sell posting calendars, profiles, reviews, and reports. | Competing on scheduling or dashboards creates commodity pressure. |

MenuList should not compete head-on there.

## Why Add-on Works

MenuList has a defensible starting point:

- current menu items
- item availability
- pricing
- categories
- images
- public menu link
- store status
- hours
- owner settings
- public business page context
- existing Today/Social Content campaign engine
- existing AI capacity and cost accounting

Generic tools ask the owner to describe the business. MenuList already has the business truth.

## Who Pays

Primary buyer:

- restaurant, cafe, bakery, cloud kitchen, or food-service owner already using MenuList
- wants more local visibility but does not have a marketer
- uses WhatsApp, Instagram, Google Business Profile, or printed in-store material
- already trusts MenuList as the source of menu truth

Best-fit tiers:

- higher-tier single-location operators
- multi-outlet brands
- managed onboarding clients
- clients paying for MenuList because public presence accuracy matters

Avoid:

- free/base users
- owners still fixing basic menu truth
- agencies and marketing teams
- users asking for design canvases, analytics, or scheduling dashboards

## What We Should Build First

Build the paid add-on around a simple action flow:

1. Open Growth Kits.
2. See one or a few current action opportunities.
3. Choose an action.
4. Generate a kit.
5. Copy, download, print, or share manually.
6. Optionally mark as used.

The freeze-ready V1 core is:

| Capability | Decision | Owner value |
| --- | --- | --- |
| Do This Now Inbox | Build first | Avoids blank-page thinking. |
| Menu Truth Readiness Checklist | Build first | Prevents wrong or incomplete public copy. |
| Owner Voice basics | Build first | Makes copy usable without prompt editing. |
| Compliance Preflight | Build first | Stops invented offers, stale prices, unavailable items, and risky wording. |
| One Kit to Multiple Handoffs | Build first | One action creates WhatsApp, Instagram, Google draft, staff, and print copy. |
| Staff Brief Pack | Build first | Helps staff say the right thing today. |
| Basic export logging | Build first | Records copy/share/download/print/mark-used only, with no ROI claims. |
| Mobile latest-kit fallback | Build first | Keeps the last usable kit visible when refresh or generation fails. |

The first kit families should be:

| Kit family | Owner moment | Outputs |
| --- | --- | --- |
| Today Action Kit | "What should I post or send today?" | WhatsApp status, WhatsApp message, Instagram caption, Google update draft |
| Menu Event Kit | "This item changed or deserves attention." | item caption, image reuse/generation option, QR link text, staff line |
| Staff Brief Kit | "What should staff say or avoid today?" | main staff line, avoid list, public menu fallback, counter prompt copy |
| In-store Push Kit | "Customers are already inside." | poster/tent copy, digital screen line |
| Local Trust Kit | "My public presence should look current." | GBP update draft, hours/status reminder copy, public link copy |
| Review Reply Guard | "I need to respond carefully." | guarded reply draft from pasted text only, hidden from daily inbox |

## Pilot-Dependent Features

Do not build these before the core loop proves real owner use:

| Feature | Decision |
| --- | --- |
| Existing Image Adaptation | Add only after text/staff kits are used. Use existing images only; no design canvas and no AI image generation in V1. |
| Owner-Confirmed Offer Builder | Defer. It creates new business truth and must not invent discounts or leave expired offers usable. |
| Review Triage expansion | Defer beyond pasted-text guard. Food-safety, legal, abusive, and refund cases need conservative handling. |
| Customer FAQ Reply Snippets | P2. Useful if owners/staff repeatedly ask for WhatsApp/DM reply shortcuts. |
| Photo Capture Prompts | P2. Useful if missing images repeatedly block kit value. |
| Multi-Outlet Localized Kits | P2. Build only with multi-outlet pilot demand and strict store-specific facts. |
| Used History UI | P2. Export rows are V1; dashboards and ROI remain rejected. |
| Advanced low-data/offline kit access | P2. V1 only keeps the latest loaded kit visible with stale warnings. |

## What We Should Not Build

Do not build:

- auto-posting
- social calendar
- performance dashboard
- ROI model
- campaign optimizer
- design canvas
- agency workspace
- prompt playground
- multi-brand brand-kit system
- direct writes to MenuList truth
- invented offers
- customer inbox/chatbot
- staff management
- loyalty/coupon system
- AI image generation as default
- new standalone product domain
- new scheduler

## Product Names

Use two names:

| Context | Name |
| --- | --- |
| Internal architecture and docs | GrowthOS Add-on |
| Owner UI and public copy | Growth Kits |

Reason: "GrowthOS" is useful internally but too abstract for a non-technical owner. "Growth Kits" says what the owner receives.

## Freeze Decision

The freeze-ready scope is not "marketing automation." It is:

> Paid MenuList clients receive accurate, ready-to-use growth kits built from their current MenuList truth.

Everything outside that sentence should remain disabled, hidden, or documented as explicitly out of scope.
