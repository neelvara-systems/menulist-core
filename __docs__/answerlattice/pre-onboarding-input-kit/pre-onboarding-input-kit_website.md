## Problem

Most teams start support setup with scattered source material. Product facts live in code, docs, websites, changelogs, help pages, pricing pages, support replies, and screenshots.

If that material reaches Answerlattice as a loose upload pile, the first intake job has to spend effort reconstructing what the product actually is.

## Solution

The Pre-Onboarding Kit gives the client's AI IDE a strict preparation workflow. The agent audits available product truth, separates live support facts from risky claims, creates upload-ready sources, and leaves clear activation gates before Answerlattice answers live users.

## Page Sections

1. **What the agent prepares**
   - product context;
   - docs and website truth;
   - target-product boundary when a repo contains multiple products;
   - feature and route coverage;
   - risky-topic boundaries;
   - live support test questions;
   - screenshot, demo walkthrough, FAQ, and website asset plans.

2. **How it works**
   - open the prompt modal;
   - copy the prompt or download it as a Markdown file;
   - paste the prompt into the AI IDE;
   - let it inspect the repo, docs, site, owner notes, or screenshots you provide;
   - if the repo has multiple products, target the named product and exclude sister products;
   - if the owner asks for FAQ, demo, or website assets, create review-ready briefs instead of approved public assets;
   - review the generated folder;
   - upload selected sources into Answerlattice;
   - approve drafts before live support.

3. **Output folder**
   - source inputs;
   - API payload skeletons;
   - production onboarding notes;
   - product surfaces;
   - asset/screenshot/demo/FAQ inputs.

4. **Safety boundaries**
   - no secrets;
   - no private customer records;
   - no payment data;
   - no unapproved screenshots;
   - no guarantee that every AI IDE can inspect every private repo, login-only app, website, recording, or file;
   - unavailable sources must be marked pending;
   - no automatic canonical publishing.

5. **Best fit**
   - teams with a product repo;
   - teams with multi-product repos or shared codebases;
   - teams with existing docs;
   - teams with only a public website;
   - teams preparing from owner notes and screenshots;
   - founders preparing launch support;
   - products with multiple user surfaces.

6. **Owner and agent guides**
   - owner preparation checklist;
   - repo, website-only, docs-only, owner-notes, and early-product run modes;
   - multi-product repo targeting and exclusion rules;
   - AI agent source-first operating rules;
   - owner review checklist;
   - live-support activation gates.

- "No review needed."
- "Upload your whole repo."
- "Replace your support team."
