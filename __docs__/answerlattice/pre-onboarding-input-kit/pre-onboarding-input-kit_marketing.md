# Answerlattice Pre-Onboarding Input Kit — Marketing Notes

## Positioning

Pre-onboarding is the moment where Answerlattice becomes easier to adopt than a blank support setup.

The buyer already has product truth. Answerlattice gives them a way to shape it before intake.

## Core Message

Prepare your product for Answerlattice before setup starts.

## Supporting Messages

- Use the AI coding agent you already trust.
- Turn the product sources you have - repo, docs, website links, owner notes, policies, and screenshots - into Answerlattice-ready inputs.
- Prepare review-ready FAQ seeds, demo walkthrough briefs, screenshot rules, and website claim candidates from source material.
- Keep sensitive data out before upload.
- Mark private, blocked, or unavailable sources as pending instead of pretending they are covered.
- Give Answerlattice structured source truth, not a pile of files.
- Review before anything becomes live support.

## Best-Fit Audience

- AI-built SaaS founders.
- Solo founders before launch.
- Products with support scattered across README files, docs, pricing pages, and app routes.
- Products that do not yet have a clean docs folder or public help center.
- Teams with one codebase containing multiple products, dashboards, domains, or packages.
- Teams that already use Codex, Cursor, Windsurf, Antigravity, Claude Code, or similar tools.

## Differentiation

Most support tools ask users to upload docs after signup. Answerlattice can guide the client before signup or before first intake, so the first workspace starts with stronger source truth.

## Sales Usage

Use this when a prospect asks:

- "What should we upload first?"
- "Can you learn from our product repo?"
- "Our repo has multiple products. How do we avoid mixing them?"
- "What if we only have a website or owner notes?"
- "Can this prepare FAQs, screenshots, demo walkthroughs, or website copy briefs?"
- "How do we prepare before onboarding?"
- "Can our AI IDE help?"
- "How do we avoid uploading private data?"

## Boundary Language

Use:

- "prepares inputs";
- "source-backed package";
- "complete for accessible sources";
- "owner-reviewed";
- "upload-ready";
- "live support gate".

Avoid:

- "automatic support setup";
- "no review needed";
- "crawl everything";
- "instant AI support";
- "replace your docs or helpdesk";
- "works perfectly with every AI IDE";
- "guaranteed complete for blocked private sources."
