# Answerlattice MCP - Marketing Boundaries

> **Status:** Controlled capability; not a default public promise
> **Last Updated:** 2026-07-20

## Accurate Positioning

Use:

> Connect approved Answerlattice context to selected MCP-compatible tools through short-lived, workspace-scoped sessions.

Supporting proof, only when enabled for a customer:

- approved private product context rather than raw document search;
- exact product/workspace and explicit `mcp:read` scope;
- bounded structured tool outputs with bundle version;
- missing-context reports become governed review evidence;
- no autonomous publishing or account actions.

## Customer Value

For a technical founder, the useful job is not "having MCP." It is reducing repeated product explanation inside trusted developer/support workflows while keeping one approved answer lifecycle.

Lead with the named workflow, for example:

- give a coding assistant the current approved integration/setup context;
- let an internal support copilot retrieve exact canonical and release context;
- report unanswered technical questions back into review.

## Do Not Claim

- generally available MCP access;
- standards-complete OAuth or universal MCP client compatibility;
- per-user/per-source authorization;
- raw Slack, ticket, code, or private-document search;
- autonomous customer support or product actions;
- real-time zero-staleness;
- perfect answer accuracy because a citation exists;
- cost savings, resolution rate, or adoption without measured customer evidence.

## Sales Qualification

MCP is a fit only when the buyer has:

- a concrete MCP-compatible server/desktop workflow;
- enough approved canonical/product context;
- a technical credential owner;
- workspace-wide permission to expose the private compiled context to that client;
- willingness to test real questions and review errors.

It is not a reason to broaden Answerlattice into a generic agent platform.
