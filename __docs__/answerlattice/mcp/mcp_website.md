# Answerlattice MCP - Website Contract

> **Status:** No standalone public feature page while disabled by default
> **Last Updated:** 2026-07-20

## Current Website Decision

Do not add MCP to primary navigation, pricing promises, homepage feature grids, schema, FAQs, or general availability copy while `ENABLE_ANSWERLATTICE_MCP` remains false.

The existing website may describe the broader truthful capability as:

> Approved context can be distributed to controlled external tools and agents when a reviewed integration is enabled.

## Allowed Evidence

After a real design-partner rollout, a case study may state:

- the named MCP client and workflow;
- time to connect;
- number/type of approved questions tested;
- task usefulness and correction rate;
- exact abstention/error behavior;
- credential, scope, and human-review controls.

## Prohibited Copy

- "Works with every MCP client"
- "Connect any agent"
- "Search all company knowledge"
- "Always current"
- "Autonomous support agent"
- "Enterprise-grade OAuth" until implemented and verified
- "No hallucinations"
- any numeric performance or savings claim without measured evidence

## Future Page Gate

A dedicated MCP page requires all of:

1. feature enabled for multiple named customers;
2. hosted compatibility proof for supported clients;
3. reviewed security/data-handling statement;
4. one measured customer outcome;
5. support and credential-recovery runbook;
6. founder decision that MCP helps distribution without redefining the product.
