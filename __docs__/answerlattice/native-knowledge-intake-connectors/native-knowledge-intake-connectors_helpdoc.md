# GitHub Change Intake - Owner Help

> **Last Updated:** 2026-08-11

## Connect GitHub

1. Open **Teach Answerlattice**.
2. In **GitHub changes**, select **Connect GitHub**.
3. Install the Answerlattice GitHub App for only the repositories that contain the product you support.
4. Return to Answerlattice and select up to ten repositories.
5. Keep **Published releases** enabled. Enable **Merged pull requests** only when release notes alone do not describe customer-visible changes.
6. Optionally require a label such as `customer-facing` or `docs-impact` to reduce pull-request noise.
7. Save the connection.

An active Answerlattice subscription is required to connect repositories and receive new change evidence.

## What Happens Next

Published releases and allowed merged pull requests appear as private sources in a GitHub changes intake job. They do not update customer answers automatically.

When you are ready:

1. Open the GitHub changes intake job.
2. Review the imported source.
3. Select **Prepare drafts** to run the existing governed analysis.
4. Review source authority, conflicts, affected Product Topics, and proposed answer or article changes.
5. Approve and publish only the changes you confirm.

## What Answerlattice Reads

Answerlattice reads release metadata and, when enabled, merged pull-request metadata plus changed file names. It does not clone the repository or store source code and patches.

## Disconnect

Disconnecting stops new GitHub intake and removes repository routing. Existing imported evidence remains available for review and audit. Remove the GitHub App from GitHub as well if you no longer want the installation to exist.
