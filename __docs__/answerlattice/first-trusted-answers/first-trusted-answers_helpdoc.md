# First Trusted Answers Owner Guide

## Start With Ten Questions

Complete **Launch Setup -> Teach Answerlattice** with your product website, docs, notes, release information, screenshots, or other approved sources. Then open **Launch Setup -> First 10 Answers**, choose the intake, and select **Generate product-specific set**.

Answerlattice prepares ten editable questions and matching draft answer proposals. Review the sources and missing-evidence warnings in Knowledge Intake before accepting anything. A generated draft is not an approved answer. Publishing it from Intake creates a Governance proposal, and Governance approval is still required before it becomes official.

Generation uses one support credit the first time the selected source and launch-context version is processed. Opening or retrying unchanged inputs uses the saved result and does not use another credit. Use the general starter set only when you do not yet have enough product material for a product-specific pack; it is unavailable after a product-specific set exists.

Choose questions that repeatedly interrupt launch work, especially around onboarding, billing, permissions, plan limits, integrations, errors, cancellation, and releases.

## Run The Free Check First

Select **Run First 10 checks** before using the full runtime. This free launch check runs the exact active ten-question set and verifies the governed answer route, expected answer or FAQ, blocked phrases, and evidence rules without calling an AI provider.

If the action is unavailable, restore or activate every question in one valid set. Do not mix general starter questions with product-generated questions. Reload before running when a selected question changed or became inactive.

## Fix Failures In The Right Place

- Missing official answer: create a proposal in Governance.
- Repeated short question: review an owner FAQ.
- Detailed explanation: review a Knowledge Base article.
- Customer-specific or risky question: keep a safe escalation or no-answer expectation.

Answer Tests do not edit live answers.

## Install After Truth Is Ready

Use Install Center to verify the script, origin, blocked routes, product context, and widget runtime. Test the same priority questions from the product pages where users ask them.

## Read Outcome Metrics Correctly

**Confirmed resolution** means an end user explicitly selected **Solved**. **Recontact** means that same widget session asked another question after a confirmed resolution. Non-escalation remains an operational routing metric, not proof that the issue was solved.

## Prepare Follow-Up Work

When Daily Brief offers **Prepare review card**, review the prefilled title and context in Support Board. No card exists until you select **Create card**.
